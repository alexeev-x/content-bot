## Data model (to build; the review's proposal, adjusted)

- `ai_generations` — one row per model call that produced text: kind, format, mode (direct/automatic), model, pack revision, task, output, a link to the `ai_usage` row (tokens and cost already live there, migration 0053).
- `ai_text_revisions` — id, generation id, parent id, provenance, text, created at, approved at.
- `ai_edit_feedback` — generation id, final revision id, diff, edit ratio, changed-part tags, owner feedback buttons.
- `content_ai_links` — final revision id, publication id, content item id (for Reels: linked by the Cron on a clear match, or confirmed by the owner in the bot or the item panel).
- `ai_learning_evidence` — id, source type (edit, analytics, owner), source id, scope (format), observation, weight.
- `ai_learning_rules` and `ai_rule_evidence` — as in item 10.
- `content_items.format` — item 1.

## Corrections from the owner's follow-up (16.10.2026), accepted

Git holds the stable editorial system; D1 holds the living memory. Analytics compares only the same format at the exact same age with enough clean items. A weak video is not excluded because it stopped growing. New content is not classified by a model when its format is known. An AI text cannot reach a publication without a real server-side owner approval.

P0 before the learning loop: exact-age same-format baseline with N ≥ 5 clean; provenance; draft → final → publication → platform item → analytics; runtime memory in D1; the server-side approval guard; confirmed-confounder semantics; AI_DRAFT never in style retrieval. Then: T+72 review, evidence, candidate/supported/strong rules, weekly «Мой опыт».
