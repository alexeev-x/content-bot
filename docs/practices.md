# Инженерные практики

Чек-лист для любого, кто пишет здесь код — человека или ИИ. Не общие слова из интернета,
а правила этого проекта с причинами. Архитектура и размещение файлов — в `../README.md`.

## TypeScript

- **`strict`, и никаких `any`.** Внешние данные приходят как `unknown` и проходят через zod.
  Обоснованное исключение — с комментарием, почему иначе нельзя.
- **Формы объектов — `type`, не `interface`.** Проверяется линтером.
- **Сужай тип на границе, а не заглушай проверку.** `ctx.chat?.id ?? 0` молча отправит сообщение
  в несуществующий чат; `Filter<Context, 'message:text'>` делает `chat` гарантированным.
- **Тип зависимости описывает потребитель.** Структурная типизация сведёт его с реализацией
  в composition root — импорта между фичами не появится.
- Значения, ограниченные протоколом (цвета тем, коды ошибок), типизируем узко, а не как `number`.

## Асинхронность и внешние вызовы

- **У каждого внешнего вызова есть таймаут.** Зависший `fetch` без него не завершится никогда:
  в этом проекте такое уже держало обработчик по 50 секунд.
- **Временная ошибка не доказывает безопасность повтора.** Для изменяющего POST сеть, таймаут
  и `5xx` означают неизвестный исход. Повтор разрешается только при идемпотентном контракте
  либо явном подтверждении, что действие не выполнено. Отказ `400`/`403` автоматически не повторяем.
- **Число попыток ограничено.** Бесконечный повтор съедает квоту и маскирует поломку.
- **Не перемножаем повторы.** `lib/api.ts` делает короткий ограниченный повтор только при
  явном `idempotent: true`. Для Telegram повтором управляет журнал и повторная доставка входа;
  транспорт таких операций не повторяет. Будущие задания с собственным backoff отключают
  транспортные повторы. Длинный `Retry-After` не сокращаем; Telegram `retry_after` сохраняем в D1.
- **Дедуп входа не равен идемпотентности эффекта.** Вход хранится со статусом и арендой,
  каждое исходящее действие — с отдельным стабильным ключом и результатом.
- ❌ Долгих `sleep` в обработчике: время следующей попытки сохраняем, а не ждём.
- **Не удаляем свидетельства неопределённого результата.** Подтверждённый успех используется
  повторно; зависшее `sending` и `unknown` требуют сверки. Процедура — в `recovery.md`.

## Cloudflare Workers

- **Глобальная переменная — не память.** Изолят живёт минуты и умирает без предупреждения.
  В глобалах допустим только кэш, потеря которого ничего не ломает (например, `botInfo`).
- **Считай subrequests**: лимит 50 на вызов. Лишний `getMe` на каждый апдейт — это лишний из 50.
- **CPU-лимит 10 мс** на бесплатном тарифе, но ожидание сети в него не входит. Тормозит обычно не
  счёт, а необдуманный round-trip.
- **Большие файлы не читаем в память** — только потоком или частями.
- Биндинги живут в `env` конкретного вызова: зависимости собираются на запрос, а не при импорте.

## База (D1 + Drizzle)

- **SQL руками не пишем.** Таблица описывается в `table.ts`, миграция генерируется `pnpm db:generate`.
- **У таблицы один владелец.** Чужие таблицы читаем через контракт владельца, а не напрямую.
- **Интерактивных транзакций в D1 нет.** Атомарность — через `batch` или один `UPDATE` с условием.
- **Внешний вызов и запись в базу — не одна транзакция.** Между ними возможен сбой: либо
  компенсируем, либо ведём задание с повтором. Молча надеяться нельзя.
- Применённые миграции не переписываем — только новая миграция сверху.
- **Индекс на колонку в `WHERE` и на уникальность.** D1 считает деньги по прочитанным строкам,
  поэтому индекс снижает и задержку, и стоимость. Проверить, используется ли он, —
  `EXPLAIN QUERY PLAN` перед запросом: в выводе должно быть `USING INDEX`, а не `SCAN`.

## Ошибки

- **Один `AppError { code, message, retryable }`** на всё приложение. Он не знает про транспорт:
  код в HTTP-статус переводит вход, в текст владельцу — Telegram, в решение о повторе — очередь.
- ❌ Глотать ошибку в обработчике. Если вернуть успех после сбоя, повторной доставки не случится,
  и работа исчезнет бесследно.
- Сообщение об ошибке наружу — безопасное. Причина и стек остаются в логах.

## Логи

- **Только структурные**, одной строкой JSON: их читают машины.
- HTTP-логи содержат `requestId`; журнал связывает действия по `update_id` или ключу операции.
  Доменные события содержат ключ раздела/операции, без текстов автора и сырых внешних ошибок.
- ❌ В логи не попадают: токены, заголовки авторизации, подписанные URL, тексты автора, тела
  ответов модели.
- Логируем факты и длительности, а не «зашли в функцию».

## Безопасность

- **Секреты только в Workers Secrets и `.dev.vars`** (в `.gitignore`). Не в `vars`, не в коде,
  не в логах, не в промптах модели.
- **Секрет webhook сравниваем за постоянное время** и проверяем до любой работы.
- **Бот личный**: чужие апдейты игнорируются молча, без ответа — чтобы не подтверждать существование.
- Необратимые операции (удаление темы со всей перепиской) не делаем командой бота: одна опечатка
  в чате не должна ничего стоить. Их место — скрипт в терминале.

## Производительность

- **Сначала измерь.** В этом проекте «медленно» три раза оказывалось не тем, на что думали:
  виноват был сломанный IPv6, а не код.
- Оптимизируем то, что повторяется на каждый апдейт, — остальное подождёт.
- Кэш на изоляте уместен для того, что не меняется в пределах жизни изолята.

## Зависимости и цепочка поставок

- Добавляем под конкретную задачу, а не «пригодится».
- Проверяем совместимость с текущими версиями рантайма: `eslint-plugin-import` молча падал
  на ESLint 10, `typescript-eslint` не поддерживает TypeScript 7.
- Версия пакетного менеджера зафиксирована в `packageManager` — обе машины ставят одно и то же.
- **Lockfile в git.** Без него «у меня работает» перестаёт что-либо значить.
- **В CI ставим `pnpm install --frozen-lockfile`**, а не обычный install: сборка не должна молча
  подтянуть другую версию.
- **Install-скрипты пакетов запрещены по умолчанию.** Разрешаем поимённо в
  `pnpm.onlyBuiltDependencies` — сейчас это `esbuild`, `workerd`, `unrs-resolver`. Скомпрометированный
  пакет не должен получать исполнение просто за факт установки.
- **Сторонние GitHub Actions пиним по SHA**, а не по тегу: тег переписывается.
- **Обновления зависимостей не авто-мержим.** Бот-PR проходит те же проверки, что и человеческий.

## tsconfig

Опции выписываем явно, а не полагаемся на умолчания версии — они меняются между мажорами TypeScript.
Сейчас включены: `strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`, `verbatimModuleSyntax`,
`isolatedModules`, `noImplicitReturns`, `noFallthroughCasesInSwitch`, `allowUnreachableCode: false`,
`forceConsistentCasingInFileNames`.

`exactOptionalPropertyTypes` намеренно выключен: на нашем коде он даёт ошибки почти только из-за
чужих типов (опции grammY), обходится условными спредами и стоит больше, чем ловит.

## Тесты

Пирамида Фаулера в оригинале требует много модульных и мало сквозных. У нас перекос в сторону
интеграционных — и это осознанно: сам Фаулер оговаривает _«if my high level tests are fast, reliable,
and cheap to modify — then lower-level tests aren't needed»_. Наши идут 1,9 секунды внутри настоящего
рантайма. Модульные заводим там, где логика ветвится сама по себе: повторы, разграничение команд,
расчёт сроков.

## Чего осознанно не делаем

DI-контейнер, классы-контроллеры, use-case-классы Clean Architecture, канонические агрегаты DDD,
event sourcing, микросервисы. Каждое решает проблему масштаба, которой у личного бота нет,
а стоит времени на каждой правке. Появится проблема — вернёмся к решению.
