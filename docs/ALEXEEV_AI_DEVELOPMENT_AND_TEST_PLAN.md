# ALEXEEV AI — что осталось и как проверяем

**Статус на 19.10.2026:** код плана ИИ (редактор в боте, «Что не так?», аналитика и прогнозы, ежедневный и недельный отчёты с разбором ИИ, привязка сценариев, правила владельца, правила из аналитики и уроки из правок, раздел в Студии) написан и проходит `npm run verify`; на DEV проверен только редактор в боте; production не затрагивался. Что и как устроено — в коде, `docs/ai/architecture.md` (п. 10 — правила) и `docs/backend/`. Здесь только то, что не сделано.

## 1. Решения владельца (не гипотезы)

1. Один логический ИИ ALEXEEV для Telegram и Studio: общие OpenAI-настройки, промпт-пакет, D1-память, версии, аналитика, права и история. Использование разных моделей OpenAI внутри одного контура допускается по назначению и бюджету; Claude Code — средство разработки, не runtime API.
2. **Telegram-first**: каждый день владелец пишет и правит сценарии преимущественно в Telegram; Studio — административная панель для глубоких деталей, истории, контроля правил, затрат и будущих автоматизаций. Нельзя создавать параллельного «ботового» ИИ с отдельной памятью.
3. Рубрики: «Учу фидить в Доту» (уверенная сатира без самоиронии), «Учусь играть в Доту» (подлинный опыт новичка), самостоятельные Reels, Telegram-посты. Учитывать существующий `docs/ai/pack`, примеры, словарь, ревизии и ограничения на выдуманный опыт.
4. Для «Учусь играть» начало озвучки **сразу сильный хук**: не вставлять перед ним приветствие, название рубрики, номер части, описательное перечисление умений. Фирменная заставка — **в конце монтажа** (сам монтаж не входит в задачу); сценарный ИИ не должен добавлять в озвучку вступительную заставку. Не создавать однообразные хуки-клоны.
5. После текста владелец может нажать «Текст готов», запросить иной хук/переписывание или «Что не так?» и свободно описать причину; ИИ корректирует текущий текст и структурирует замечание для памяти. Не требовать числовую оценку каждого текста.
6. Ежедневно Telegram-бот присылает отчёт по **6 последним опубликованным Shorts на YouTube и 6 последним TikTok** (по шесть на платформу, до 12 всего), с текущими просмотрами, приростом за 24 часа, ссылками, состоянием скорости, прогнозными диапазонами и краткими выводами/гипотезами. Администратор выбирает время и часовой пояс; допускается отдельная команда «Аналитика сейчас».
7. ИИ учитывает подтверждённые выводы, собственные ошибки прогнозов и обратную связь владельца при подготовке будущих текстов. Не переносить выводы между платформами/рубриками без основания; не приравнивать гипотезу к факту.
8. Пока без автопубликации созданных ИИ текстов без отдельного явного решения владельца. Обычный `approve` и существующие серверные ограничения обязательны.
9. **Ничего не объявляется готовым без проверяемого доказательства:** автоматические тесты, DEV-интеграция, реальные контролируемые вызовы, независимая проверка и отдельно финальная пользовательская приёмка.

## 2. P9 — независимая проверка (делает агент, до приёмки владельца)

Итог — отчёт `docs/ai/eval/P9_REPORT.md`: что проверено, чем, результат с выводом команд; не проверенное помечено «не проверено» с причиной. Найденная ошибка исправляется отдельным коммитом с тестом, который её ловит.

**A. Автоматические проверки целиком.**
- `npm run verify` (все шаги) на чистом дереве; e2e Playwright (`npm run test:e2e -w @alexeev/frontend`).
- Бюджеты Cron: прогнать подряд тики минут 2, 4, 8, 9, 14, 24, 34, 44, 54 на данных «всё включено» (отчёт, недельный отчёт в понедельник, подсказки сценариев, разборы, уроки, потерянные задания) через `meteredDb` — каждый тик ≤ 50 операторов D1.
- Потребитель очереди: каждый тип задания (draft, rewrite, facts, fix, chat, daily_review с недельной сводкой правил, style_lessons) — ≤ 50 операторов D1 в худшем случае.

**B. Миграции 0073–0084.**
- Применение на пустой базе и на копии схемы до 0073 с данными (ролики, сценарии, черновики, отчёты): ничего не теряется, ограничения проходят, бэкфил 0083 метит только автопривязки.
- `EXPLAIN QUERY PLAN` для новых запросов списков и Cron: используется индекс, не полный просмотр таблиц.

**C. Сценарии от начала до конца на локальной D1 с подставной моделью.**
- Четыре недели по дням: сбор данных → ежедневный отчёт → разбор → прогнозы получают факт → понедельничный отчёт → сводка правил → вопрос «Учитывать?» → правило в промпте следующего черновика.
- Правки владельца: 5 правок → уроки → вопрос → «Учитывать» → правило в промпте; «Нет» → урок больше не предлагается.
- Привязка сценария: авто → «✅ Верно» → связь учит правила; «Не тот сценарий» → связь снята.

**D. Сбои (каждый должен закончиться понятным сообщением, без двойной оплаты и без повторной отправки в Telegram).**
- Модель: таймаут, 429, 5xx, неверный JSON, ответ не по схеме, нет ключа, неизвестная модель, бюджет месяца/дня исчерпан.
- D1: ошибка посреди батча, задание захвачено и Worker упал (сообщение «Черновик не дописался»), повторная доставка из очереди, два одновременных тика Cron.
- Telegram: 400/403/429/5xx/таймаут при отправке отчёта и вопросов — `unknown` не переотправляется, `failed` виден.

**E. Безопасность.**
- Каждый новый маршрут Студии: 401 без сессии, 403 не владельцу, 400 на неверный ввод (правила, отчёты, черновики).
- Бот: команды и кнопки только от владельца в личном чате; устаревшие и чужие кнопки — «Эта кнопка устарела.»; данные кнопок ≤ 64 байт.
- Текст владельца, замечания, названия роликов и сценарии в промптах не меняют правила, бюджеты и права; правило не длиннее 300 символов.
- Логи: ни ключа, ни текста задания, ни initData — поиск по выводу тестов и коду логирования.

**F. Интерфейс Студии.** Разделы «Правила редактора», «История черновиков», «Аналитика → Отчёты», «Ежедневный отчёт» в настройках: 375 / 1280 / 1920, светлая и тёмная тема, axe без нарушений, клавиатура, нет горизонтальной прокрутки; пустые состояния и ошибки загрузки. Это проверка на тестовых данных; вид на DEV оценивает владелец.

**G. Независимое ревью.** Отдельный ревьюер (qa-security) по всей ИИ-части: модули `ai`, `content-analytics` (отчёты, прогнозы), `app/bot` (редактор, правила), `app/workflows`, миграции 0073–0084.

## 3. P3 — качество текстов (нужен владелец)

Контрольный прогон по `docs/ai/eval/README.md`: 21 задание из `control-set.jsonl` на DEV, черновики рядом с оригиналами владельца; владелец вслепую отмечает «мой стиль / почти / мимо». Повторить после первых недель работы с уроками из правок и сравнить; второй показатель — средняя доля правки по неделям.

## 4. Прогнозы на реальных данных (нужна история на DEV)

Проверка метода прогноза (backtest) на накопленных роликах DEV против простого базового прогноза: доля попаданий в диапазон по горизонтам 24 ч / 72 ч / 7 дней; метод остаётся, только если не хуже базового.

## 5. Проверки владельца на DEV (по одному пункту, в конце)

1. `/analytics`: две таблицы, ссылки под ними.
2. Настройки → Общие → «Ежедневный отчёт»: включить, время; отчёт пришёл в это время с разбором ИИ.
3. Понедельник 10:00: «Итоги недели».
4. Новый ролик: «Привязал сценарий» с «✅ Верно» или вопрос «Снят по этому сценарию?».
5. `/rule …` → выбор рубрики → правило в тексте; `/rules` → отключить.
6. Пара сильных правок или «Что не так?» → в течение часа вопрос «✍️ …Учитывать?».
7. Студия: «Правила редактора», «История черновиков», «Аналитика → Отчёты».
8. Разборы видео через 72 часа: решение владельца, включать ли их (выключены по умолчанию, одна дешёвая модель на ролик).
