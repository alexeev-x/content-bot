## Owner-confirmed issues

### S1. Settings buttons look different (sev 3, DS + FE)
Cause is not one variant: it is the size split plus a wrong doc.
- Settings uses the default `size="md"` (36 px, `padding: 0 var(--space-5)` = 20 px, `Button.module.css:6,8`) for: «Добавить канал» `pages/settings/ChannelsPage.tsx:24` and `features/destinations/ui/ChannelsList.tsx:53` (a primary, filled accent, 190 px wide, right-aligned alone in an empty toolbar `ChannelsPage.module.css:1-4`); «Сохранить» `ChannelEditor.tsx:208`; «Отменить изменения»/«Сохранить» `AppearanceEditor.tsx:190,193`; dialog footers.
- The same screens also use `size="sm"` (30 px, 12 px padding, `Button.module.css:25-29`): «Свой цвет» `CustomPresetsCard.tsx:29`, «Проверить права бота» and drawer buttons, popover buttons. Result in `settings-appearance-default-1280-light.png`: a 30 px outlined button at y≈1052 and 36 px buttons at y≈1232 on one page; `settings-channels-drawer-1280-dark.png` shows 36 and 30 px side by side.
- `Button.tsx:12` says «md is 44 px»; on a fine pointer it is 36. Authors choose by that false comment.
- Primary «Добавить канал» is the biggest accent fill on the page (Density: no large accent fills; ≈5%).
- Fix (DS): two sizes with a rule. `md` = 32 px, padding 16 px (page toolbars, form footers, dialogs); `sm` = 28 px, padding 10 px (inside rows, popovers, banners). Next to a text field use `size="field"` = field height (36) so «Проверить» matches its input (`settings-channels-add-form-1280-light.png`: button 36 vs field 36, ok, but «Cancel/Add» in the footer are 36 too, fine; keep them md). Fix the comment. Fix (FE): «Добавить канал» becomes `variant="secondary"` md with a plus icon when the list is non-empty (primary only in the empty state), moved into the section header row on the same line as «Каналы» (`.toolbar` is a lone row costing 56 px); «Свой цвет» becomes md.
- Benchmark: GitHub Primer Button, one primary per page, primary last in a group: https://primer.style/product/components/button/guidelines/ . Vercel Geist Button, sizes small/medium/large with fixed heights: https://vercel.com/geist/button .

### S2. Dashboard «Всё работает»: unclear, full width (sev 3, FE)
- `dashboard-healthy-1280-light.png`: a green 8 px dot, a muted 14 px line and «Проверено 12:00» pushed to x=1256. The whole 1016 px row is the opener button (`SystemStatus.module.css:32-37`, `.line` flex:1; `SystemStatus.tsx` `opener`), so the hit area is a long invisible bar with no hover or chevron. The page below is empty: a sole status line is the dashboard.
- Healthy state is the common state, so it should be the quietest and still readable: say what was checked and that it is clickable.
- Proposal, compact status widget: a pill-button, content-width, height 28 px (`sm`), radius `--radius-pill`, 1 px `--color-border-subtle`, no fill. Content: dot 8 px `--color-status-done-fg` + «Система в порядке» + muted mono «12:00» + chevron-down 14 px. Place it in the PageHeader actions slot (top right, aligned with the «Обзор» title), not as a body row. Hover: `--color-surface-2`; focus ring; `aria-expanded`. Click opens the existing popover (360 px) with the checks list, each row «name · result · time» and a «Проверить сейчас» ghost button. Problem state: same pill, dot + text change to `-failed`/`-unknown` tokens, text «Бот не подключён» (or «Требует внимания: 2»), one 28 px action button next to it only when there is exactly one problem. No tinted full-width banner (`SystemStatus.module.css:9-22`, seen in `dashboard-several-problems-1280-dark.png`: a red 1016 px bar with ghost «Разобраться» that does not read as a button).
- Popover duplication (`dashboard-status-open-1280-dark.png`): bot summary printed twice (row summary + bold details) plus a «Требует проверки» badge: show it once.
- Dashboard is otherwise empty: spec says «Сегодня», 3-5 decisions, next publications. That is a product gap, not a style one; until then the widget in the header plus an `EmptyState` is honest.
- Benchmark: Vercel Geist status dot + label, compact: https://vercel.com/geist/status-dot ; Primer ActionMenu for the details popover: https://primer.style/product/components/action-menu/ .
