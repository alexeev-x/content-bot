# Приёмка и принципы

Владелец ставит задачи и не обязан ловить за тобой ошибки. Решение, за которое не стыдно, —
твоя ответственность. Если задача поставлена неправильно — скажи об этом до того, как сделаешь.

## Перед тем как сказать «готово»

Прогони. Не «вроде помню», а проверь.

- [ ] `pnpm check` зелёный — типы, границы слоёв, формат, тесты
- [ ] Затронутый инвариант покрыт тестом; новый инвариант добавлен в таблицу `docs/testing.md`
- [ ] **Проверка действительно проверяет.** Сломай нарочно и убедись, что ловится. Здесь дважды
      «зелёный» означал, что команды не существует или она упала иначе
- [ ] Новый файл размещён по процедуре из `README.md`, выбор назван вслух одной строкой с причиной
- [ ] Ни одного импорта вбок: `modules` ⟂ `modules`, `app` ⟂ `modules`
- [ ] У данных **один владелец**; чужие данные — только через контракт
- [ ] Побочное действие защищено стабильным ключом; неизвестный результат сохраняется и требует сверки
- [ ] Ошибка не проглочена: наружу безопасное сообщение, `retryable` выставлен осознанно
- [ ] У внешнего вызова таймаут; повтор ограничен и разрешён только при доказанной безопасности
- [ ] Необратимое действие недоступно одним нажатием из пользовательского интерфейса
- [ ] Секреты не попали в код, логи и коммит
- [ ] Менялось архитектурное решение — обновлён `README.md`; удалена функциональность —
      удалено и её описание в документах
- [ ] Проверено на живом примере, а не «должно работать»

## Что здесь считается нарушением

Называй это вслух, даже если задача была про другое.

| Нарушение                   | Почему это дефект                                                |
| --------------------------- | ---------------------------------------------------------------- |
| Состояние в памяти процесса | Изолят умирает без предупреждения — данные исчезнут молча        |
| У данных два владельца      | Рано или поздно двое запишут разное, и никто не виноват          |
| Скрытая связь между фичами  | Фичу нельзя удалить папкой, а значит нельзя и понять её границы  |
| Проглоченная ошибка         | Успех после сбоя отменяет повтор: работа исчезает бесследно      |
| Повтор без ограничения      | Съедает квоту и маскирует поломку вместо того, чтобы её показать |
| Внешний вызов без таймаута  | Один зависший запрос держит обработчик до чужого таймаута        |
| Необратимое действие в UI   | Опечатка не должна стоить данных                                 |
| Оптимизация без измерения   | Чинится не то: здесь «медленно» трижды оказывалось не кодом      |
| Слой знает о том, что выше  | Утилита с HTTP-статусами перестаёт работать в очереди и cron     |
| Файл «на будущее»           | Пустая абстракция дороже отсутствующей: её поддерживают          |

## Как возражать

- **Задача противоречит архитектуре** — скажи до начала, предложи вариант, который не противоречит.
- **Просят быстрое решение с известной ценой** — сделай, но назови цену в одну строку.
  Молчаливый компромисс завтра выглядит как ошибка.
- **Не знаешь** — не угадывай. Проверь по документации или скажи, что не знаешь.
- **Ошибся** — исправь и назови причину одной фразой, без самобичевания и без замалчивания.

## Чего не делать в отчёте

- Не говори «готово», если не прогнал чек-лист.
- Не докладывай об успехе, если проверял только тип-чекер.
- Не скрывай, что часть работы не сделана: назови, что осталось и почему.
